# Maestaris v0.7.0 — Chat-first reset

v0.7.0 is the release where Maestaris becomes deliberately small again.

## What Maestaris is

Maestaris lets ordinary interactive AI coding chats turn normal chat usage into durable GitHub work.

The complete default loop is:

```text
Issue -> worker chat -> branch/commit/PR -> orchestrator review -> merge
```

GitHub is durable memory and coordination. It is not a second orchestration engine.

## What changed

- Worker A and Worker B are ordinary coding conversations.
- The orchestrator is an ordinary planning/review conversation.
- GitHub Issues define bounded tasks and acceptance criteria.
- A lightweight claim comment prevents duplicate worker effort.
- Workers create normal branches, commits, tests, and pull requests.
- The orchestrator reviews actual diffs and CI, then merges or requests changes.
- Scheduled/background runs are optional convenience only.

## What was removed

The default architecture no longer includes:

- admission or fair-share scheduling;
- dispatcher backpressure;
- review leases;
- protocol relays;
- capability/model routing;
- external Laya/Jev/Needle3 executors;
- separate reviewer daemons;
- checkpoint/provenance/telemetry subsystems;
- simulation/runtime-conformance layers;
- scheduler bootstrap machinery;
- the Python orchestration package and CLI.

These removals are intentional. They keep Maestaris focused on doing project work rather than building infrastructure around the chats.

## Migration from v0.6.x

1. Keep `AGENTS.md`, `coordination/maestaris.yaml`, and the role prompts.
2. Treat GitHub Issues, comments, branches, PRs, CI, and merged history as the durable source of truth.
3. Stop depending on the removed Python package, CLI, relay workflows, schedulers, leases, or executor services.
4. Use ordinary chat invocations for Worker A, Worker B, and the orchestrator.

See `docs/quickstart.md`, `docs/protocol.md`, and `docs/architecture.md` for the complete v0.7.0 workflow.
